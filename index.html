Summary

Jonathan — here's how I'd build the assistant you described. It ingests your communications, keeps a running model of your tasks, the people you deal with, and how you like things handled, then produces drafts and actions that you approve before anything happens. This covers scope, architecture, the one hard constraint, security, and a 2-week build plan.

Scope
In scope · v1
  • Read Outlook (all mailboxes) and Slack (DMs + channels)
  • Business VoIP call + text transcripts
  • Task + priority tracking, with a daily brief
  • Draft emails, replies, and texts — approval required to send
  • Answers and feedback across a set of topics you define
  • Actions in selected web apps via API, approval-gated
Out of scope · v1
  • Personal-cell call audio or iMessage/SMS (see constraint)
  • Any autonomous sending
  • Connections to PFG systems before a security review
  • Voice replies / real-time call assistance
Constraint · calls & texts

Capturing voice and SMS

Live call audio and iMessage/SMS on a personal phone aren't reachable by software — the OS blocks it. To capture calls and texts, we route them through a VoIP number (Dialpad, Aircall, or OpenPhone) that records and transcribes, and the assistant reads the transcripts over the provider's API. Recording also needs a consent review before we enable it — several states require all-party consent.

Architecture

Three stages: ingest, reason, act

Ingest is read-only. The reasoning layer holds memory and task state. Every outbound action passes an approval step before it leaves the system.

The agent holds no send credentials. Drafts and actions are written to an approval queue that reaches you over Slack or text; a separate service performs the send only after you approve. Approval is enforced by which service holds the keys, not by instructions to the model.

Security
  • Self-hosted on infrastructure we control; Anthropic API under zero-retention, no-training terms
  • Least-privilege, revocable credential per integration; no send credential in the agent's path
  • Encryption at rest; audit log of every item read and every action proposed
  • Security review before any connection to PFG systems
